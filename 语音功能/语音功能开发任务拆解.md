## 1. 本期目标

把语音从独立货架收归为角色属性：

- 角色创建/编辑时可配置语音：音色 + 发语音频次。
- 用户可在「我的声音」管理自己的复刻音色资产。
- 用户和 AI 都可以在聊天中收发语音消息。
- 预设音色免费配置；复刻音色创建保存扣 1 张音色卡，修改已有复刻音色扣 1 张音色卡。
- 音色卡权益：VIP 每月赠送 2 张，SVIP 每月赠送 4 张；可单独购买，价格文案为 6 元/张。
- 角色/assistant 语音消息播放按点击扣糖果：每次点击播放扣 2 颗糖果，同一条语音重复点击也重复扣；用户自己发出的语音播放不扣糖。
- 存量角色不兼容语音，不展示入口、不接收 AI 主动语音。

## 2. 关键产品规则

- 预设音色：免费，可试听，保存角色不额外扣卡。
- 复刻音色：试听免费，保存扣 1 张音色卡，改名/修改已有音色扣 1 张音色卡；无卡时按会员/非会员状态引导获取。
- 复刻素材：本期仅支持上传音频 / 从视频提取，不做现场录音复刻。
- 复刻素材建议：3-60 秒纯人声，30 秒左右最佳，避免 BGM/噪声/多人声。
- 复刻每日免费重做次数：3 次；点「开始生成」消耗 1 次，生成失败不消耗；保存成功后重置为 3。
- 未保存的试听结果有效期：7 天，过期提示重新创建。
- 「我的声音」最多 99 个复刻音色；达到上限后禁用创建入口。
- 删除音色前必须解绑所有使用该音色的角色。
- 语音频次：从不 / 偶尔 / 经常；从不表示 AI 不主动用语音回复，但用户仍可发语音。
- 聊天页不显示每条语音扣费 toast，避免破坏沉浸；余额不足、加载失败退款等异常才提示。
- 「查看文字」展开语音转写不扣糖果。
- 同一时间只播放一条语音；播放新语音时自动停止上一条。
- 语音加载中重复点击不重复扣费；已扣费但加载失败时退还本次 2 颗糖果。
- 角色音色页、调配音色页、录音创建页内的“试听”不消耗糖果。
- 聊天录音单次最长 60 秒，到上限自动停止并进入识别/发送流程。
- 联调白名单手机号 `18871098779` 免扣糖果和音色卡，但仍走同一接口状态，便于验链路。

当前已落地的最小闭环：

- 客户端上传音频到 `POST /chat/v1/upload/audio`。
- 客户端发送 `POST /chat/v1/chats/:chatId/messages`，字段为 `content_type=voice`、`media_url`、`duration`、`mime_type`。
- 服务端在 chat runtime 中把 voice 消息 ASR 成文字；配置 `VOLC_ASR_API_KEY` 或旧版 `VOLC_ASR_APP_ID + VOLC_ASR_ACCESS_TOKEN` 时走火山极速识别，无配置时走 mock ASR。
- 模型侧读取转写后的 `content`，客户端侧读取 `media_url/asr_text/content` 展示播放和文字。
- 会话配置 `voice_id` 后，用户发语音会触发 AI 第一条文本回复转 `voice`，服务端用火山 TTS V3 HTTP 合成音频并上传，客户端按 `content_type=voice` 播放和查看文字。

### 4.3 API

- 预设音色：
  - `GET /chat/v1/voices/presets?gender=male|female`
  - 返回音色名、gender、preview_url、是否选中、provider voice id 不直接暴露给客户端。
  - 当前 `moodly-chat-svr` 已升级：`GET /chat/v1/voices` 继续返回数组以兼容旧客户端，同时返回 `id/name/gender/preview_url/sample_text/type/provider/provider_speaker_id` 等字段；`GET /chat/v1/voices/presets` 返回 `{ items }`。
- 角色语音设置：
  - 在角色创建/编辑接口加入 `voice_enabled`、`voice_id`、`voice_type`、`voice_frequency`。
  - 或复用 `/chat/v1/chats/:id/settings`，但需要确保创建角色阶段也能保存语音设置。
  - 返回创建/编辑页所需摘要：未设置、预设音色、复刻生成中、已配置复刻。
- 我的声音：
  - `GET /chat/v1/voices/my/summary`
  - `GET /chat/v1/voices/my`
  - `GET /chat/v1/voices/my/:id`
  - `PATCH /chat/v1/voices/my/:id` 改名，最多 20 字。
  - `DELETE /chat/v1/voices/my/:id`，在用时返回在用角色列表，不直接删除。
  - 当前 `moodly-chat-svr` 第一版已实现上述接口，返回字段匹配 Android/iOS 当前模型：`has_membership/voice_card_balance/cloned_voice_count/items/in_use_characters`。
- 复刻流程：
  - `GET/POST /chat/v1/voices/clone/uploads/presign` 返回当前直传说明；第一版未做 TOS 预签名 PUT，先使用服务端 multipart 上传。
  - `POST /chat/v1/voices/clone/uploads` multipart 上传音频/视频；视频服务端抽音频并返回 `extracted_audio_url/object_key`。
  - `POST /chat/v1/voices/clone/jobs` 创建复刻任务。
  - `GET /chat/v1/voices/clone/jobs/:id` 查询状态，并在火山训练中时尝试回刷状态。
  - `POST /chat/v1/voices/clone/jobs/:id/generate` 开始生成试听；配置齐时提交火山训练，未配置时生成 mock 试听。
  - `POST /chat/v1/voices/clone/jobs/:id/save` 保存为我的音色；保存成功消耗 1 张音色卡，重复保存同一 job 幂等返回已保存音色。
  - `POST /chat/v1/voices/clone/jobs/:id/retry` 重置任务以便重新生成。
- 语音消息：
  - `POST /chat/v1/chats/:chatId/voice-upload/presign` 获取聊天录音上传 URL。
  - `POST /chat/v1/chats/:chatId/messages` 支持 `content_type=voice`、`media_url`、`audio_duration_seconds`、`audio_mime_type`，可选 `asr_text`。
  - 服务端缺少 `asr_text` 时触发 ASR；AI 上下文使用转写文本，展示层保留语音消息。
  - 返回 user message + assistant messages 时包含音频字段。
  - `POST /chat/v1/chats/:chatId/messages/:messageId/voice-playback/charge` 播放角色/assistant 语音前扣 2 颗糖果；余额不足返回 `insufficient_candy`，白名单返回免扣成功。
  - `POST /chat/v1/chats/:chatId/messages/:messageId/voice-playback/refund` 音频加载失败后按 `playback_id` 幂等退还本次扣费。
- 试听：
  - 预设音色试听直接返回 `preview_url`。
  - 复刻试听使用固定试听文案生成，缓存 TTS 结果。
  - 角色当前音色卡片试听不扣糖果。
  - 若火山 `ListBigModelTTSTimbres` 能返回 `DemoURL`，预设试听优先用官方 demo URL；如果没有 demo URL，则服务端用固定文案 `你回来啦，今天过得怎么样？` 调 TTS 生成一条试听音频并上传到 TOS。
- 站内消息：
  - 复刻完成且用户不在 Step 4 时生成消息中心卡片。
  - 支持未读红点、24 小时自动已读、手动删除、点击跳转 Step 4。

### 4.4 业务逻辑

- AI 是否发语音必须同时满足：
  - 角色 `voice_enabled=true`
  - 角色配置了可用音色
  - `voice_frequency != never`
  - 用户糖果余额足够
  - 当前回复内容适合语音，且不属于高信息密度/分点说明
  - 不命中青少年模式、风控、敏感内容等限制
- 频次概率需要产品确认一版默认值，例如：
  - `never`: 0
  - `sometimes`: 低概率，仅情绪/晚安/用户刚发语音等场景
  - `often`: 更高概率，但仍由场景 gate 控制
- 用户发语音：
  - 上传成功后创建本地 pending message。
  - 服务端 ASR 成功后进入正常 LLM 回复。
  - 发送用户自己的语音消息本身不扣糖果；客户端仍可免费播放自己发出的语音。
- AI 发语音：
  - LLM 输出口播文本。
  - 服务端 TTS 生成音频并入库为 `content_type=voice`，`content/asr_text` 保存可展开文字。
  - 消息生成本身不扣糖果；用户点击播放该角色语音时扣 2 颗糖果，加载失败按 `playback_id` 退还。
- 角色码兑换：
  - 人设先到账。
  - 若含复刻音色，按非会员/会员无卡/会员有卡弹 I1/I2/I3。
  - 兑换音色时复制 speaker/model 引用或生成用户资产副本，不传输原始素材。

### 4.5 复刻素材处理、视频/音频提取与文字识别方案

Status: current

Owner topic: 语音复刻素材处理与聊天语音 ASR。当前 owner 代码在 `moodly-chat-svr`，双端只负责选择文件、轻量预检、上传、播放和状态展示。

本能力分三条链路，不要混在一起看：

- 复刻音色素材处理：用户上传一段音频，或从视频里提取声音，最终得到一份可提交火山声音复刻的训练音频。
- 聊天语音文字识别：用户发语音消息时，服务端 ASR 转文字，文字进入 LLM 上下文，同时保留原语音给客户端播放。
- 复刻素材质检识别：未来对复刻素材再跑 ASR/音频质检，用于确认有人声、时长、静音、噪声和用户可确认的文字片段；这不是聊天消息入模链路。

#### 4.5.1 当前实现状态（2026-06-03）

- `POST /chat/v1/voices/clone/uploads` 已支持 multipart 上传复刻素材。
- 音频源支持：`aac/m4a/mp3/ogg/wav/webm`。当前服务端保存原音频，并把 `extracted_audio_*` 指向同一份音频，作为后续复刻训练输入。
- 视频源支持：`mp4/mov/m4v/webm`。客户端会先尝试本地抽音频；如果本地抽取不可用，则上传视频给服务端，服务端用 `ffmpeg` 抽成 24k mono `m4a` 中间音频。
- Android 本地视频抽取：`MediaExtractor + MediaMuxer`，仅在视频音轨为 AAC/MP4A 时直接 remux 为 `.m4a`；其他编码回退服务端。
- iOS 本地视频抽取：`AVAssetExportSession` 使用 `AVAssetExportPresetAppleM4A` 输出 `.m4a`；失败则回退服务端。
- 服务端视频抽取：`moodly-chat-svr/src/infra/voice-video.ts` 调 `ffmpeg`，显式选择第一条音轨 `0:a:0`，禁用视频/字幕/数据轨，输出 `24k/mono/aac/96k/m4a`。
- 部署要求：生产/测试机必须安装 `ffmpeg`；否则服务端视频回退链路会返回 `ffmpeg is required to extract audio from video`。
- 火山复刻 provider：`moodly-chat-svr/src/infra/volc-voice-clone.ts` 已接提交训练/查询状态 wrapper。真实 provider 当前遇到 403 时记录错误并走 mock clone fallback，保证 upload -> generate -> preview -> save 主链路可用。
- 质检边界：当前只做格式、大小、空文件、视频无音轨等基础校验；时长、人声、多人声、BGM/噪声、授权确认和 ASR 辅助确认仍待接入。

#### 4.5.2 音频素材方案

适用入口：

- “我的声音 -> 创建新音色 -> 上传音频”
- 后续角色码/运营导入复刻素材也应复用同一条服务端处理链路。

客户端职责：

1. 使用系统文件选择器选择音频文件。
2. 做轻量预检：文件是否可读、大小是否明显超限、时长是否可读取。
3. 展示素材建议和授权确认：建议 3-60 秒纯人声，30 秒左右最佳，避免背景音乐、噪声、多人声；用户需确认有权使用该素材。
4. 通过 `POST /chat/v1/voices/clone/uploads` multipart 上传文件。
5. 上传成功后进入命名页，展示可试听素材和默认名称。

服务端职责：

1. 校验 MIME/扩展名，只接受 `aac/m4a/mp3/ogg/wav/webm` 等音频格式。
2. 校验空文件和大小上限，使用 `UPLOAD_AUDIO_MAX_BYTES` 控制。
3. 保存原始音频到对象存储，返回：
   - `source_type=audio`
   - `source_media_url/source_object_key/source_mime_type/source_size_bytes`
   - `extracted_audio_url/extracted_audio_object_key/extracted_audio_mime_type`
4. 当前第一版 `extracted_audio_*` 与原音频相同；后续如果火山复刻对采样率/声道更严格，服务端再增加统一转码步骤，把任意音频标准化为 `24k mono m4a/wav`。
5. 创建 `VoiceCloneJob` 时始终以 `extracted_audio_*` 作为训练输入，避免 provider 直接依赖原始上传格式。

推荐后续增强：

- 用 `ffprobe` 读取时长、声道、采样率、音频编码。
- 对超过 60 秒的素材先提示用户剪辑，不在服务端静默截断。
- 增加音量/静音检测，静音或有效人声太短直接失败。
- 对音频源也可跑一次 ASR，用转写片段帮助用户确认“这段素材确实是想复刻的人声”。

#### 4.5.3 视频提取声音方案

适用入口：

- “我的声音 -> 创建新音色 -> 从视频提取”

客户端职责：

1. 使用系统文件选择器选择视频文件。
2. 做轻量预检：格式、大小、时长可读；不在客户端做最终质检。
3. 优先尝试本地抽音频，降低服务端压力和视频上传失败概率：
   - Android：如果音轨是 AAC/MP4A，直接 remux 为 `.m4a`。
   - iOS：如果系统可导出，使用 Apple M4A preset 输出 `.m4a`。
4. 本地抽取成功时，上传 `.m4a`，但 UI 和 draft 仍保留 `sourceType=video`，文案显示“视频音频”。
5. 本地抽取失败时，上传原视频，由服务端抽音频。
6. 视频上传/抽取失败时展示可读原因，不显示 provider 原始错误。

服务端职责：

1. 校验 MIME/扩展名，只接受 `mp4/mov/m4v/webm` 等视频格式。
2. 校验空文件和大小上限，使用 `UPLOAD_VIDEO_MAX_BYTES` 控制。
3. 保存原视频到对象存储，保留 `source_media_url/source_object_key`，用于问题排查和短期重试。
4. 调 `ffmpeg` 抽音频：
   ```bash
   ffmpeg -y -nostdin -hide_banner -loglevel error \
     -i source.mp4 \
     -map 0:a:0 -vn -sn -dn \
     -ac 1 -ar 24000 -c:a aac -b:a 96k \
     -movflags +faststart -f ipod audio.m4a
   ```
5. 抽取成功后把 `.m4a` 上传到对象存储，返回：
   - `source_type=video`
   - 原视频 `source_*`
   - 抽出的音频 `extracted_audio_*`
6. 抽取失败时按原因返回：
   - 没有音轨：`video has no extractable audio track`
   - 环境缺 `ffmpeg`：`ffmpeg is required to extract audio from video`
   - 格式不支持或文件损坏：`video audio extraction failed`
7. 创建/生成复刻时始终提交 `extracted_audio_*`，不把视频直接交给 provider。

推荐后续增强：

- 用后台 job 做视频抽取和训练，不让 HTTP 请求长时间阻塞。
- 对原视频设置短生命周期：未保存 job 7 天过期；保存成功后按合规策略删除或私有归档原视频。
- 增加任务恢复：用户退出生成页后，重新进入可查询 job 状态并继续试听/保存。

#### 4.5.4 聊天语音文字识别（ASR）方案

适用入口：

- 用户在聊天页长按录音并发送语音消息。
- 客户端“查看文字”读取服务端保存的 `asr_text/content`，不在客户端本地识别。

客户端职责：

1. 录音生成本地 `m4a/aac` 文件。
2. 调 `POST /chat/v1/upload/audio` 上传聊天录音，拿 `media_url`。
3. 调 `POST /chat/v1/chats/:chatId/messages`，传：
   - `content_type=voice`
   - `media_url`
   - `duration` 或 `audio_duration_seconds`
   - `mime_type` 或 `audio_mime_type`
   - 可选 `asr_text/asr_confidence`，生产主路径通常不传。
4. 发送成功后展示语音气泡，播放 `media_url`；展开“查看文字”时显示 `asr_text`，若暂时没有则触发刷新消息列表。

服务端职责：

1. `routes.ts` 兼容顶层 `duration/mime_type/asr_text/asr_confidence`，统一写入 message runtime extra。
2. `reactive-input.ts` 处理 `content_type=voice`：
   - 如果客户端已传 `asr_text`，直接使用。
   - 如果没有 `asr_text`，通过 `transcribeAudioFromUrl(media_url)` 拉取音频并调用 ASR。
   - ASR 成功后，消息 `content` 使用识别文本进入 LLM，上下文不使用占位文案“我发了一条语音消息”。
   - 展示层保留原始 `media_url/duration/mime_type/asr_text/asr_confidence`。
3. ASR provider 当前为火山极速语音识别：
   - 新版控制台优先 `VOLC_ASR_API_KEY`
   - 资源使用 `VOLC_ASR_RESOURCE_ID=volc.bigasr.auc_turbo`
   - 请求头使用 `X-Api-Key` 和 `X-Api-Resource-Id`
4. mock fallback 只用于联调/本地兜底，必须显式配置 `VOLC_ASR_MOCK_FALLBACK_ENABLED=true`；生产默认不应把 provider 错误伪造成固定文字。
5. 客户端音频错误仍应失败并暴露可读原因，例如空音频、无声、格式不支持、音频不可下载；这些错误不能被 mock fallback 吞掉。

存储与响应：

- User voice message：
  - `content_type=voice`
  - `content=ASR 文本`
  - `media_url=用户原始录音`
  - `asr_text=ASR 文本`
  - `asr_confidence=provider 置信度或 null`
- Assistant voice message：
  - `content_type=voice`
  - `content=AI 原始回复文本`
  - `media_url=TTS 生成音频`
  - `mime_type=audio/mpeg` 或配置格式
  - `asr_text` 可等同 `content`，用于“查看文字”

#### 4.5.5 复刻素材质检中的文字识别

复刻素材 ASR 不等同于聊天 ASR。它的目标不是进入 LLM，而是帮助判断素材是否适合训练。

推荐质检顺序：

1. 基础文件校验：格式、大小、空文件。
2. 媒体校验：时长、音轨存在、声道/采样率可读。
3. 音频能量校验：过滤静音、极低音量、明显截断。
4. ASR 抽样识别：确认有人声，保存一小段 `validation_json.asr_preview_text`。
5. 质量提示：ASR 文本为空或置信度太低时，提示“未识别到清晰人声，请换一段纯人声素材”。
6. 后续增强：多人声、BGM/噪声、名人相似风险检测。

`validation_json` 建议结构：

```json
{
  "duration_seconds": 28,
  "audio_codec": "aac",
  "sample_rate": 24000,
  "channels": 1,
  "asr_preview_text": "今天过得怎么样",
  "asr_confidence": 0.82,
  "quality_flags": ["low_noise", "single_voice_likely"]
}
```

第一版失败原因需要稳定映射给双端：

- `unsupported_source_type`：暂不支持该文件格式
- `source_too_large`：文件太大
- `source_empty`：文件为空
- `duration_too_short`：声音太短，建议 3-60 秒
- `duration_too_long`：声音太长，建议裁剪到 60 秒内
- `video_no_audio_track`：视频里没有可提取的人声
- `ffmpeg_missing`：服务端缺少视频提取依赖
- `no_clear_speech`：未识别到清晰人声
- `provider_forbidden`：火山复刻 provider 权限/资源配置问题
- `provider_unavailable`：火山服务暂不可用

### 4.6 风控、隐私与合规

- 上传素材前或保存前增加授权确认文案/用户协议补充：上传素材即表示已获得被录音人授权。
- 原始素材设置生命周期，保存成功后只保留必要 provider id 和预览音频，原始音频按合规策略删除或私有归档。
- 禁止公开暴露原始素材 URL；播放 URL 用短期签名或 CDN token。
- 复刻错误需映射为用户可读 toast：时长不符、未检测到人声、噪声/BGM、多人声、音频质量低、名人相似风险、provider 限流。
- 增加后台管理/客服查询：任务状态、扣卡记录、扣糖记录、失败原因。

### 7.1 默认预设音色配置

目标：App 内先给用户免费使用几条预设音色，可试听，不消耗音色卡。火山侧仍按账号开通的公版音色额度/计费规则走，客户端文案不承诺“火山永久免费”。

当前生产实现（2026-06-03 收口版）：

- `moodly-chat-svr` 会在请求音色列表时 upsert 静态兜底预设音色，当前优先使用已验证可合成的 Seed 2.0 原生 speaker：
  - `zh_female_vv_uranus_bigtts`：Vivi 2.0。
  - `zh_female_xiaohe_uranus_bigtts`：小何 2.0。
  - `zh_male_taocheng_uranus_bigtts`：陶承 2.0。
  - `zh_male_m191_uranus_bigtts`：M191 2.0。
- 每条预设写入 `voices`，`type=preset`、`provider=volc_tts`、`providerSpeakerId=SpeakerID`、`sampleText=你回来啦，今天过得怎么样？`。
- `preview_url` 不存在且 TTS 配置可用时，服务端会用固定试听文案生成试听音频并上传；生成失败不阻塞列表返回。
- 聊天 TTS 已支持用业务 `voice.id` 查 `providerSpeakerId`，客户端不需要长期持有火山 speaker id。
- 存量/旧客户端仍可能保存 `BV***_streaming` 或旧 `zh_*_mars/moon_bigtts`，服务端会在 `volc-tts.ts` 映射到 Seed 2.0 speaker，例如 `BV700_V2_streaming -> zh_female_vv_uranus_bigtts`。
- 生产 smoke 已确认：`voice_id=BV700_V2_streaming`、`voice_frequency=often` 时，assistant 第一条回复可 materialize 为 `content_type=voice`，火山返回 `auth_mode=api_key`，音频为 `audio/mpeg` mp3。

推荐实现：

- 优先在服务端启动或定时调用火山 `ListBigModelTTSTimbres`，读取 `SpeakerID / SpeakerName / Gender / DemoURL / DemoText`，筛选中文、通用/对话类音色，写入 `voices` 表为 `type=preset`。
- 若拉取失败，使用静态兜底清单，等真实 TTS smoke 通过后再上线。当前已 smoke 通过的兜底为上述 `zh_*_uranus_bigtts` 清单；`BV***_streaming` 不再作为上线兜底，只作为兼容输入映射。
- 每条预设音色保存：
  - `provider=volc_tts`
  - `providerSpeakerId=SpeakerID`
  - `previewUrl=DemoURL`；没有 DemoURL 时用固定试听文案生成并上传。
  - `sampleText=DemoText` 或 `你回来啦，今天过得怎么样？`
  - `isVipOnly=false`
- 客户端只拿 `voice.id/name/gender/preview_url/sample_text`；聊天 TTS 时服务端根据 `voice.id` 查 `providerSpeakerId`，禁止客户端直接持有 provider speaker id 作为长期业务 ID。

- ASR 文本可用于 LLM 上下文，查看文字免费。

## 10. 待确认问题

- 火山云 TTS 已采用豆包语音合成大模型 HTTP V3 + API Key 模式；声音复刻真实 provider 仍需继续确认最终接口版本、训练字段和状态查询字段。
- `voice_frequency` 服务端枚举是否改为 `never/sometimes/often`，还是保留 `never/sometimes/always` 后前端映射「经常」。
- 用户发语音的 ASR 失败时是否仍发送音频，还是阻断发送。
- 复刻素材原文件保存多久，是否保存成功后立即删除。
- 预设音色清单、命名、gender 标签、试听文案由产品还是服务端 seed 管理。
- 音色卡是否已有商品/订阅权益发放规则；需要和 iOS StoreKit、Android Alipay、服务端 VIP 账本联动。
- 站内消息中心现有实现在哪个仓库/模块，需要确认后接入复刻完成通知。
