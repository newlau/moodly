## 2. 当前真相

### 2.1 iOS

| 类型 | 当前实现 |
| --- | --- |
| 统一入口 | `AnalyticsManager.shared.track(event, params)` |
| 隐私门禁 | `PrivacyConsentStore.isAccepted` 为 false 时直接丢弃事件 |
| 友盟初始化 | `AnalyticsManager.initializeIfConsented()` 内调用 `UMConfigure.initWithAppkey` |
| 友盟上报 | `MobClick.event(event, attributes:)` |
| 后端上报 | 异步 `POST /v1/analytics/events`，`requiresAuth: true` |
| 公共参数 | 当前自动加 `platform=ios`、`app_version` |
| 失败处理 | 后端上传失败只在 Debug print，不影响主流程 |
| 全局页面 | `AnalyticsManager.trackPageShow/trackPageHide` 已接；根登录页/主 Tab 和 `analyticsPage` modifier 可用 |
| 全局按钮 | `trackButtonClick` 已接；公共 ButtonStyle、`AppButton`、返回/更多/图标按钮可兜底 |

iOS 的 `APIClient` 默认基地址是 `AppConfig.apiV1BaseURL = baseURL + /v1`，所以 iOS 服务层写 `path: "/app/startup-strategy"` 实际请求是 `/v1/app/startup-strategy`；`AnalyticsManager` 写 `path: "/v1/analytics/events"` 时也会直接命中服务端注册路由。

### 2.2 Android

| 类型 | 当前实现 |
| --- | --- |
| 统一入口 | `AnalyticsTracker.track(event, params)` |
| 隐私门禁 | `AuthTokenStore.currentPrivacyAccepted` 为 false 时直接丢弃事件 |
| 友盟初始化 | `UmengInitializer.initializeIfConsented()` |
| 友盟页面模式 | `MobclickAgent.setPageCollectionMode(MobclickAgent.PageMode.MANUAL)` |
| 友盟上报 | `MobclickAgent.onEvent(context, event, attributes)` |
| 后端上报 | 异步 `POST v1/analytics/events` |
| 公共参数 | 自动加 `platform=android`、`app_version`、`is_login`、`is_vip` |
| 失败处理 | 后端上传失败只在 Debug log，不影响主流程 |
| 全局页面 | `GlobalAnalytics.trackPageShow/trackPageHide` 已接；`MoodlyNavHost` 和 `MainScreen` 根 Tab 会自动上报 |
| 全局按钮 | `GlobalAnalytics.trackButtonClick` 已接；`noRippleClickable`、`AppButton`、`AppIconButton`、`AppBackButton`、`AppMoreButton`、`RootTabBar` 可兜底 |

### 2.3 主服务端

| 类型 | 当前实现 |
| --- | --- |
| 路由注册 | `analyticsRoutes` 以 `/v1/analytics` prefix 注册，事件接口为 `/v1/analytics/events` |
| 请求格式 | 支持单条事件，也支持 `{ events: [...] }` 批量最多 50 条 |
| 校验 | `event_name` 必填，最大 128；`properties` 最大 8KB |
| 幂等 | `analytics_events.client_event_id` 唯一索引 |
| 存储 | `ANALYTICS_DATABASE_URL` 指向独立 analytics DB，启动时自动建 `analytics_events` 表 |
| 写入字段 | event_name、client_event_id、user_id、anonymous_id、platform、app_version、channel、session_id、device_id、request_id、properties、occurred_at、received_at |

注意：`AnalyticsAgent.trackMany()` 对重复 `client_event_id` 使用 `ON DUPLICATE KEY UPDATE received_at = received_at`，返回值仍是本批 records 数量，不区分新插入和重复命中。

### 2.4 客户端错误日志

已新增独立客户端错误日志最小闭环，和友盟行为埋点分开：

| 能力 | 当前真相 |
| --- | --- |
| 服务端结构化日志 | 新增 `POST /v1/client-logs/events`，写入 `client_log_events` |
| iOS 结构化日志 | 新增 `ClientLogger`；`APIClient` 失败、活动入口无链接、活动 banner 图片失败、WebView 加载失败已接 |
| Android 结构化日志 | 新增 `ClientLogger`；活动入口无链接、活动 banner 图片失败、OkHttp 网络/HTTP 失败、WebView 加载失败已接 |
| 服务端 diagnostics | 已有 `/v1/diagnostics/capture`，但用于服务端 CPU profile、heap snapshot、内存摘要，不是 App 日志 |
| 用户反馈 | 已有 `/v1/feedback`，支持文字和截图到飞书，但不是自动日志采集 |
| Android 本地日志 | 多处 `Log.d/Log.w/Log.e` 仍主要用于本地调试，尚未全量接入 `ClientLogger` |
| iOS 本地日志 | 多处 `print` / Debug 日志仍未全量接入 `ClientLogger` |
| 反馈联动日志 | 当前反馈未附带最近客户端日志摘要 |

## 4. 活动入口当前链路

### iOS

```text
StartupStrategyCoordinator.checkIfNeeded / refreshProfileActivityEntry
  -> StartupStrategyService.fetchActiveActivityConfigs(scene=profile_entry, platform=ios)
  -> ProfileView.mainContent
  -> activityEntryCard
  -> LegalWebViewScreen(document: .custom(...))
```

当前行为：

- 青少年模式开启时隐藏活动入口。
- 有 `imageUrl` 时展示远程 banner，失败或比例不合规时 fallback。
- 点击活动卡时优先使用 `jumpUrl`，否则使用 `webUrl`。
- 目标 URL 为空或非法时只弹 Toast：“活动链接暂未配置”。
- 没有 `AnalyticsManager.shared.track(...)`。

### Android

```text
ProfileViewModel.fetchProfile
  -> refreshProfileActivityEntry
  -> StartupStrategyRepository.fetchActiveActivityConfigs(scene=profile_entry, platform=android)
  -> AppFeatureFlags.applyProfileActivityEntry
  -> ProfileScreens.ProfileActivityEntryCard
  -> onOpenActivityWeb(title, url)
```

当前行为：

- 青少年模式开启时隐藏活动入口。
- 有 `imageUrl` 时展示完整 banner，图片失败或比例不合规时 fallback。
- 点击活动卡时优先使用 `jumpUrl`，否则使用 `webUrl`。
- 目标 URL 为空时只弹 Toast：“活动链接暂未配置”。
- 已接 `activity_entry_show`、`activity_entry_click`、`activity_entry_invalid`。
- 图片加载失败会写入 `ClientLogger`。

## 5. 根因判断

活动页面“曝光和点击不可见”的直接根因：

- 活动入口和 WebView 链路是后续新增能力，本次已先复用 `AnalyticsManager` / `AnalyticsTracker` 补上活动入口曝光/点击/无链接。
- `docs/startup_strategy_popup.md` 只在“后续扩展建议”里写了“增加埋点上报”，没有落到事件清单和客户端实现。

全局页面和按钮不可见的结构性原因：

- 原来友盟 Android 已设置手动页面采集，但项目没有建立统一页面曝光封装；本次已在 Android `MoodlyNavHost` / `MainScreen` 和 iOS 根登录/主 Tab 层补 P0 兜底。
- 原来 Button/Card/MenuRow 大多直接写点击闭包，只在会员/糖果关键链路手动插了专用事件；本次已在双端公共按钮/clickable 层补 P0 兜底。
- 仍缺少足够细的 `button_name`、`module`、`target_page` 业务语义，P0 只能保证“看得见”，P1 需要把高价值按钮改成稳定业务 ID。

失败/错误不可见的结构性原因：

- 网络层、Repository、ViewModel、UI Toast/Alert 原来各自处理错误；本次已先在 iOS `APIClient` 和 Android OkHttp 层补 `global_api_error` 兜底，UI Toast/Alert 仍待统一。
- 后端上报失败被吞掉，只 Debug 日志；客户端没有队列和重试。
- 支付失败已有专用事件；本次已补 iOS API 失败、Android 网络/HTTP 失败、双端活动图片失败、活动无链接、双端 WebView 失败，全局 Toast/Alert 尚未统一。
- 本次已新增独立 `ClientLogger` 和服务端 `client_log_events`，但本地队列、重试、面包屑、反馈联动还未做。
- 服务端 `/v1/diagnostics/capture` 是服务端性能诊断，不能替代客户端错误日志。
- `/v1/feedback` 是用户主动反馈，不能替代自动日志，但后续应附带最近脱敏日志摘要。

## 6. 建议优先级

- 已补活动入口：`activity_entry_show`、`activity_entry_click`、`activity_entry_invalid`。

- 已补 API 错误聚合：`global_api_error`，覆盖 iOS `APIClient` 和 Android OkHttp 网络/HTTP 失败。
- 已补 WebView 资源失败聚合：`global_resource_load_fail`，覆盖活动/协议 WebView 主文档失败。
- 已新增客户端错误日志最小闭环：服务端 `POST /v1/client-logs/events`、`client_log_events` 表、双端 `ClientLogger`。
- 已接入 iOS API 错误、Android 网络/HTTP 错误、双端 WebView 错误、双端活动图片/无链接错误日志。
- 待补全局 `global_ui_error_show` 聚合事件。
- 同步友盟后台创建 P0 新事件。

P1：

- 给高价值页面和按钮补稳定业务语义：`module`、`button_name`、`target_page`、`object_type/object_id`。
- 补 iOS 直接 `onTapGesture`、Android 原生 `clickable/IconButton/TextButton`、H5 内部按钮。
- 首批继续细化 `activity_webview`、`startup_popup`、`chat_detail`、`chat_settings`、`feedback`。
- iOS 公共参数补齐 `is_login/is_vip/session_id`。

P2：

- 客户端实现本地队列、批量 flush、失败重试、去重/采样。
- 服务端补查询/看板 SQL 或后台页面。
- 评估 `accepted` 是否需要真实反映插入数量而不是 records 数量。
- 客户端错误日志接入本地 ring buffer、落盘、批量、短期保留、反馈联动。

## 6.1 埋点与客户端日志分工

| 类型 | 用途 | 当前状态 | 下一步 |
| --- | --- | --- | --- |
| 行为埋点 | 页面曝光、按钮点击、漏斗统计 | 部分已接 | 补全活动和全局事件 |
| 错误埋点 | 错误率、影响人数、版本分布 | 未统一 | `global_api_error` / `global_ui_error_show` |
| 客户端错误日志 | 排查原因、还原现场、关联 request_id/trace_id | P0 已接 | 继续补本地队列、面包屑、反馈联动 |
| 用户反馈 | 用户主动描述问题、提交截图 | 已有 | 附最近日志摘要或 `log_batch_id` |

关键约束：

- 同一个错误可以同时打错误埋点和客户端日志，但字段不同。
- 埋点只放可聚合维度，日志放脱敏现场。
- 两边用 `request_id`、`trace_id`、`client_event_id/log_id` 关联。
- 客户端日志不进入友盟；友盟只看聚合后的错误事件。

## 7. 暂不建议本次直接做的事

- 不直接全量替换所有 Button，风险大且容易引入双算。
- 不改友盟 appkey、channel、隐私初始化时机。
- 不改支付事件现有语义。
- 不把 SDK 原始错误、支付原始回调、完整 URL、聊天原文作为埋点参数。
- 不把所有 Toast 文案直接当错误字段上传。
- 不把原始 logcat、完整 console log、完整 URL query、聊天输入、支付 payload 直接作为客户端日志上传。
- 不用 `/v1/diagnostics/capture` 承接 App 日志；它只用于服务端性能诊断。

## 8. 待复核点

- 线上 `ANALYTICS_DATABASE_URL` 是否已配置，需用服务端运行环境或日志确认。
- 友盟后台是否已创建已有 20 个事件，新增 P0/P1 事件需要运营侧同步创建。
- H5 活动页如需统计内部按钮，需要确认是否能加 JS bridge 或 H5 自己调用后端埋点。
- iOS `AnalyticsManager.trackBackend` 当前 `requiresAuth: true`，未登录状态下是否符合“游客上报”预期需要真机/日志确认。
- 服务端重复 `client_event_id` 当前响应 `accepted` 不区分重复，数据看板如果用响应做成功插入数会有偏差。
- 客户端日志表放主业务库还是独立 analytics/log 数据库需要定；建议和 analytics 分库或至少独立表并设短保留期。
- 客户端日志是否允许上传脱敏堆栈摘要需合规复核，默认先不上完整 stack。
