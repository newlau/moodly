# Moodly 全局埋点方案与事件清单

状态：current

更新日期：2026-06-17

适用范围：iOS、Android、主服务端 `POST /v1/analytics/events`、客户端错误日志上报、友盟后台自定义事件。

说明：本文是全局埋点 owner 文档。已有会员/糖果/支付事件保持现有语义；新增事件按分期落地，真实代码、配置、日志、运行结果优先于本文。

## 1. 当前结论

当前双端已经有统一上报层：

- iOS：`AnalyticsManager.track()` 同时调用友盟 `MobClick.event` 和后端 `/v1/analytics/events`。
- Android：`AnalyticsTracker.track()` 同时调用友盟 `MobclickAgent.onEvent` 和后端 `v1/analytics/events`。
- 主服务端：`moodly_server` 注册 `POST /v1/analytics/events`，写入独立 `analytics_events` 表；支持单条和最多 50 条批量上报。

当前已经接入的业务域主要是会员、糖果、支付链路、我的页会员/糖果入口、我的页活动入口、聊天内糖果不足会员引导。

2026-06-17 已落地 P0 第一批：

- 服务端新增 `POST /v1/client-logs/events` 和 `client_log_events` 表初始化。
- iOS 新增 `ClientLogger`，接入 API 失败、活动入口无链接、活动 banner 图片失败、WebView 加载失败。
- Android 新增 `ClientLogger`，接入活动入口无链接、活动 banner 图片失败。
- 双端活动入口新增 `activity_entry_show`、`activity_entry_click`、`activity_entry_invalid`。

2026-06-17 已落地 P0 第二批：

- 双端新增统一事件：`global_page_show`、`global_page_hide`、`global_button_click`、`global_button_result` 常量。
- iOS 在 `AnalyticsManager` 增加页面曝光/离开、按钮点击 helper，并通过根 Tab、公共 ButtonStyle、`AppButton`、返回/更多/图标按钮做全局兜底。
- Android 新增 `GlobalAnalytics`，通过 `MoodlyNavHost`、`MainScreen` 根 Tab、`noRippleClickable`、`AppButton`、`AppIconButton`、`AppBackButton`、`AppMoreButton`、`RootTabBar` 做全局兜底。
- 全局事件仍走原 `AnalyticsManager` / `AnalyticsTracker`，继续受隐私同意门控制，同时上报友盟和 `/v1/analytics/events`。

当前主要缺口：

- 全局页面曝光/按钮点击 P0 兜底已接，但 iOS 直接 `onTapGesture`、Android 原生 `clickable/IconButton/TextButton`、H5 内部按钮仍需要逐步补语义命名或桥接。
- “我的”页活动入口曝光、点击、无链接已接；WebView 打开、关闭、停留时长埋点仍待补。
- 启动策略弹窗 / migration web 半浮窗文档里标了“后续增加埋点”，代码还没接。
- 已有独立客户端错误日志 P0 通道，但全局错误事件、本地队列、重试、面包屑、反馈联动仍待补。
- 客户端目前是单条即时异步上报；服务端支持批量和幂等，但客户端尚未做本地队列、重试、批量、采样。

## 2. 目标

1. 全局看得见：页面曝光、页面停留、按钮点击、关键弹窗曝光点击都能被查询。
2. 活动看得见：活动入口、活动 H5/WebView、活动失败链路可追踪。
3. 错误看得见：网络失败、接口业务失败、资源加载失败、用户可见错误有统一口径。
4. 日志可排查：客户端错误日志进入自有日志管道，能还原错误现场、request_id、trace_id、页面和设备上下文。
5. 不污染数据：不上传手机号、token、openid/unionid、支付原始回调、聊天原文、身份证号、完整 URL query 等敏感信息。
6. 低侵入落地：先补活动与全局封装，再逐步覆盖所有页面和按钮，不做一次性大重构。

## 3. 上报链路

```text
iOS/Android UI/VM
  -> AnalyticsManager / AnalyticsTracker
  -> 友盟自定义事件
  -> POST /v1/analytics/events
  -> moodly_server AnalyticsAgent
  -> analytics_events
```

服务端能力：

| 能力 | 当前真相 |
| --- | --- |
| 接口 | `POST /v1/analytics/events` |
| 鉴权 | 复用 Bearer token；服务端文档说明无 token 按游客处理 |
| 单条上报 | 支持 |
| 批量上报 | 支持 `events` 数组，最多 50 条 |
| 幂等 | `client_event_id` 唯一键 |
| 属性大小 | `properties` 单条最多 8KB |
| 存储 | 独立 `moodly_analytics.analytics_events` |
| 不足 | 客户端尚无本地队列、失败重试、批量 flush |

## 3.1 埋点与客户端日志边界

埋点和客户端错误日志不冲突，二者用途不同：

| 类型 | 解决问题 | 示例 | 存储建议 |
| --- | --- | --- | --- |
| 行为埋点 | 用户做了什么、转化漏斗如何 | 页面曝光、按钮点击、活动点击、支付成功率 | `analytics_events` + 友盟 |
| 错误埋点 | 有多少用户遇到某类错误 | `global_api_error`、`global_ui_error_show` | `analytics_events` + 友盟 |
| 客户端错误日志 | 为什么失败、当时现场是什么 | request_id、endpoint_key、error_code、网络类型、页面、最近面包屑 | 新建 `client_log_events` |
| 用户反馈 | 用户主动描述问题并带截图/联系方式 | `/v1/feedback` | 反馈系统/飞书，可附最近日志摘要 |

同一个错误允许同时产生：

```text
global_api_error
  -> 用于统计：某接口错误率、影响人数、版本分布

client_log_event
  -> 用于排查：错误堆栈/脱敏上下文、request_id、trace_id、最近页面路径
```

关联规则：

- 两边都带 `request_id`，网络请求失败时优先使用服务端响应里的 `request_id` 或客户端生成的 request id。
- 两边都带 `client_event_id` / `log_id`，方便客户端本地重试幂等。
- 埋点字段保持短小稳定；日志字段可以更丰富，但必须脱敏、限长、限量。
- 不把原始 logcat、完整 console log、完整 URL query、聊天原文、支付 payload 直接上传。

## 4. 统一参数口径

所有自定义事件都建议带上以下公共参数。当前 Android `AnalyticsTracker` 已自动带 `platform/app_version/is_login/is_vip`；iOS 当前自动带 `platform/app_version`，`is_login/is_vip/session_id` 属于待补齐项。

| 参数 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| platform | string | 平台，SDK 层自动填 | `ios`、`android` |
| app_version | string | 客户端版本，SDK 层自动填 | `1.1.0` |
| channel | string | 渠道 | Android `normal`、iOS `App Store` |
| session_id | string | 一次前台会话 ID，待接 | UUID |
| page | string | 当前页面稳定 ID | `profile`、`activity_webview` |
| source | string | 来源枚举，不能随意传文案 | `mine`、`profile_activity` |
| entrance | string | 入口来源，默认与 source 一致 | `chat_quick_candy` |
| referrer_page | string | 上一个页面稳定 ID | `profile` |
| module | string | 页面内模块 | `membership_card`、`activity_banner` |
| position | string | 位置或索引 | `profile_activity_entry`、`0` |
| button_name | string | 按钮稳定 ID，不用中文文案 | `open_activity`、`close` |
| object_type | string | 被操作对象类型 | `activity`、`vip_plan` |
| object_id | string | 业务对象 ID；禁止传敏感原文 | `activity_config_id` |
| result | string | 结果 | `success`、`fail`、`cancel`、`timeout` |
| error_type | string | 错误类型 | `network`、`server`、`business`、`webview` |
| error_code | string | 服务端业务码或本地稳定码 | `CANDY_INSUFFICIENT` |
| fail_reason | string | 脱敏失败原因；不传原始回调 | `order_create_failed` |
| duration_ms | number/string | 停留/耗时 | `12345` |
| is_login | string | 当前登录态 | `true`、`false` |
| is_vip | string | 当前会员态 | `true`、`false` |

## 8. 新增事件方案

### 8.1 全局页面曝光

| 事件名 | 中文说明 | 触发时机 | 参数 | 优先级 |
| --- | --- | --- | --- | --- |
| `global_page_show` | 页面曝光 | 页面首次可见或重新进入前台 | page, source, route_key, module, object_type, object_id | P0 已接双端兜底 |
| `global_page_hide` | 页面离开 | 页面消失、切后台、被新页面覆盖 | page, route_key, duration_ms, exit_type | P0 已接双端兜底 |

去重规则：

- 同一页面同一 `object_id` 在一次可见生命周期内只打一次 `global_page_show`。
- 列表滚动露出的卡片不走 `global_page_show`，用业务曝光事件或 `global_impression` 承载。
- 页面停留用 `global_page_hide.duration_ms`，不要把停留时长塞进下一页曝光。

### 8.2 全局按钮点击

| 事件名 | 中文说明 | 触发时机 | 参数 | 优先级 |
| --- | --- | --- | --- | --- |
| `global_button_click` | 全局按钮点击 | 任意可交互按钮、卡片、菜单行、图标按钮点击 | page, module, button_name, position, source, target_page, target_url_type, object_type, object_id | P0 已接双端公共组件兜底 |
| `global_button_result` | 点击后异步结果 | 点击触发网络、支付、上传、跳转校验后拿到结果 | page, button_name, action_name, result, error_type, error_code, fail_reason, duration_ms | P1 |

按钮命名规则：

- 用稳定 ID：`open_membership`、`open_activity`、`submit_feedback`。
- 优先不用中文文案：不要把“去看看”“立即开通”当长期 `button_name`；P0 公共组件兜底会对缺少语义名的按钮生成稳定 key，后续再逐步替换成业务稳定 ID。
- 支付、会员、糖果等已存在专用事件的关键按钮继续保留专用事件；是否同时打 `global_button_click` 由实现阶段通过采样/去重决定，避免核心漏数也避免双算。

### 8.3 活动入口与活动页面

| 事件名 | 中文说明 | 触发时机 | 参数 | 优先级 |
| --- | --- | --- | --- | --- |
| `activity_entry_show` | 活动入口曝光 | “我的”页活动卡进入可见区域 | page=`mine`, source=`mine`, activity_id, activity_name, scene, position, has_image, target_type | P0 已接 |
| `activity_entry_click` | 活动入口点击 | 点击活动卡 | page=`mine`, source=`mine`, activity_id, button_name, link_status, target_type | P0 已接 |
| `activity_entry_invalid` | 活动入口无可跳转地址 | 点击活动卡但目标 URL 为空/非法 | page=`mine`, activity_id, error_code | P0 已接 |
| `activity_webview_show` | 活动 WebView 曝光 | 活动 H5 容器打开 | page=`activity_webview`, activity_id, source, url_host, url_path_key | P0 已接 |
| `activity_webview_close` | 活动 WebView 关闭 | 用户返回/关闭 WebView | activity_id, duration_ms, exit_type | P0 已接 |
| `activity_webview_load_fail` | 活动 WebView 加载失败 | WebView 主文档加载失败 | activity_id, error_type, error_code, http_status, url_host, url_path_key | P0 已接，且写客户端日志 |
| `activity_webview_action_click` | H5 内关键动作点击 | H5 通过 JS bridge 上报按钮点击 | activity_id, action_name, button_name, result | P1 |

URL 规则：

- 只上报 `url_host` 和脱敏后的 `url_path_key`，不上传完整 URL query。
- `activity_id` 使用 `AppActivityConfig.id`。
- H5 内按钮优先由 H5 走 JS bridge 统一调用客户端埋点；没有 bridge 前至少补 App 容器打开、关闭、加载失败。

### 8.5 失败和错误

| 事件名 | 中文说明 | 触发时机 | 参数 | 优先级 |
| --- | --- | --- | --- | --- |
| `global_api_error` | 接口错误 | API 请求失败、业务 code 非 0、解析失败 | page, action_name, endpoint_key, http_status, error_type, error_code, retryable | P0 已接 iOS APIClient、Android OkHttp 兜底 |
| `global_ui_error_show` | 用户可见错误 | Toast、Alert、错误卡片展示 | page, surface, action_name, error_type, error_code, message_key, severity | P0 |
| `global_resource_load_fail` | 资源加载失败 | 图片、WebView、音频、远程素材失败 | page, resource_type, url_host, url_path_key, error_type, error_code | P0 已接 WebView 失败；其他资源 P1 |
| `global_operation_result` | 业务操作结果 | 保存资料、反馈提交、实名认证、签到等操作完成 | page, action_name, result, error_type, error_code, duration_ms | P1 |

错误上报规则：

- `endpoint_key` 使用稳定接口名，如 `startup_strategy`, `activity_configs_active`, `send_message`，不直接上报完整 URL。
- `message_key` 使用本地稳定错误 key；如必须传文案，需确认不含用户输入和个人信息。
- 支付失败继续使用现有 `vip_pay_fail/candy_pay_fail`，只补全脱敏 `fail_reason`，不要传 SDK 原始 payload。

## 8.6 客户端错误日志上报

客户端错误日志是独立于友盟事件的自有能力，P0 已新增：

- 服务端接口：`POST /v1/client-logs/events`
- 服务端表：`client_log_events`
- 双端 SDK：`ClientLogger`
- 反馈联动：`POST /v1/feedback` 可附带最近 1-3 分钟脱敏日志摘要或 `log_batch_id`，待接

### 8.6.1 日志事件模型

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| log_id | 客户端生成 UUID，用于幂等 | UUID |
| occurred_at | 客户端发生时间 | ISO8601 |
| level | 日志级别 | `error`、`warn`、`info` |
| category | 日志分类 | `network`、`webview`、`resource`、`payment`、`auth`、`chat`、`analytics_upload` |
| page | 当前页面稳定 ID | `activity_webview` |
| action_name | 当前动作 | `fetch_activity_configs`、`open_activity_webview` |
| endpoint_key | 接口稳定 ID，不传完整 URL | `activity_configs_active` |
| request_id | 服务端 request_id 或客户端生成 ID | `req_xxx` |
| trace_id | WebSocket/聊天/服务端链路 trace | `trace_xxx` |
| error_type | 错误类型 | `network`、`server`、`business`、`decode`、`timeout` |
| error_code | 业务码或本地稳定码 | `ANALYTICS_UNAVAILABLE`、`WEBVIEW_LOAD_FAILED` |
| http_status | HTTP 状态码 | `500` |
| message_key | 脱敏错误 key | `activity_url_empty` |
| context | 结构化上下文，单条建议不超过 8KB | JSON |
| breadcrumbs | 最近行为摘要，最多 20 条 | page/action 列表 |

### 8.6.2 采集范围

P0 必接：

- API 请求失败：网络错误、HTTP 非 2xx、业务 code 非 0、JSON decode 失败。
- 活动链路：活动配置拉取失败、活动 URL 空/非法、WebView 主文档加载失败。
- 资源加载：活动 banner 图片失败、关键图片/音频加载失败。
- 埋点上传自身失败：只写本地日志，按限频上报，避免递归。
- 用户可见错误：Toast/Alert/错误卡片展示时记录 `message_key`，不要直接上传用户输入。

P1 扩展：

- 登录、支付、聊天、语音、角色创建、反馈提交等关键业务错误。
- App 前后台切换、冷启动策略失败、WebSocket 断连重连摘要。
- 反馈提交时附最近日志摘要。

### 8.6.4 服务端落地

建议接口：

```json
{
  "events": [
    {
      "log_id": "uuid",
      "occurred_at": "2026-06-17T10:00:00+08:00",
      "level": "error",
      "category": "network",
      "page": "profile",
      "action_name": "fetch_activity_configs",
      "endpoint_key": "activity_configs_active",
      "request_id": "req_xxx",
      "error_type": "server",
      "error_code": "INTERNAL_ERROR",
      "http_status": 500,
      "context": {
        "scene": "profile_entry",
        "retryable": true
      },
      "breadcrumbs": [
        {"page": "profile", "action": "page_show"},
        {"page": "profile", "action": "activity_entry_visible"}
      ]
    }
  ]
}
```

服务端规则：

- 单批最多 50 条。
- 单条 `context + breadcrumbs` 总大小限制 8KB。
- `log_id` 唯一幂等。
- 按用户、匿名设备、平台、版本、level、category、received_at 建索引。
- 默认保留 7-30 天；行为分析长期看 `analytics_events`，日志不长期堆。
- 高风险字段服务端再做一次黑名单过滤：手机号、token、openid、unionid、身份证号、完整 URL query、聊天原文。

### 8.6.5 与反馈联动

## 12. 客户端日志与埋点不冲突的约束

- 统计看埋点，排查看日志。
- 错误率、影响人数、转化损失放 `analytics_events`。
- 错误现场、request_id、trace_id、脱敏上下文放 `client_log_events`。
- 用户主动反馈走 `/v1/feedback`，可附最近日志摘要，不替代自动日志。
- 日志只保留短期，默认 7-30 天；埋点可长期用于趋势分析。
- 埋点可以进友盟；客户端错误日志不进友盟，除非是聚合后的错误事件。

## 13. 合规边界

- 不上传手机号、短信验证码、token、openid/unionid、身份证号、支付原始回调、聊天原文、用户输入原文。
- 不上传完整 URL query；活动 URL 只保留 host 和脱敏 path key。
- 不上传图片、音频、截图内容。
- 错误原因使用稳定错误码或脱敏枚举，避免把服务端原始 message 直接当分析字段。
- 客户端日志不得上传原始 logcat、完整 console log、完整堆栈中可能包含的用户输入；堆栈只允许上传脱敏后的错误类型、文件/函数摘要或安全白名单字段。
- 隐私协议未同意前不上报；友盟初始化必须继续受隐私门禁控制。
