## 1. 聊天壁纸透明度

- 产品行为：聊天设置 → 聊天壁纸，在已设置图片壁纸时显示「背景透明度」滑杆（20%–100%，默认 100%）。拖动结束保存到当前会话；恢复默认壁纸或选择纯色背景时透明度回到 100%。
- 渲染：只把壁纸图片层乘以用户透明度（沿用原有 0.64 设计强度与渐变蒙层），页面底色不变，保证文字可读。
- 接口：`GET /chat/v1/chats/:id/settings` 新增 `chat_background_opacity`（number，0.2–1，默认 1）。`PUT /chat/v1/chats/:id/settings` 接受同名可选字段；缺省不修改。服务端存 `character_chat_settings.chat_background_opacity`（DOUBLE NOT NULL DEFAULT 1）。
- 客户端缓存：iOS 走 `ChatSettingsResponse`；Android 同时更新 Room `chat_settings_snapshots`（DB v9，新增列迁移）与 DataStore 快照，避免离线/冷启动先按 100% 闪一下。
- 代码位置：
  - iOS `Bubbly/Services/ChatService.swift`、`Views/Chat/ChatSettingsView.swift`、`Views/Chat/ChatDetailView.swift`。
  - Android `data/model/ChatModels.kt`、`data/repository/ChatRepository*.kt`、`ui/chat/ChatSettingsViewModel.kt`、`ui/screens/ChatSettingsScreen.kt`、`ui/chat/ChatDetailViewModel.kt`、`ui/screens/ChatDetailScreen.kt`、`data/local/ChatSettingsSnapshotEntity.kt`、`data/local/MoodlyDatabase*.kt`。
  - 服务端 `src/config/chat-settings.ts`、`src/config/defaults.ts`、`src/modules/chat/dto/routes.ts`、`src/modules/chat/routes.ts`、`prisma/schema.prisma`、`prisma/migrations/20261112_chat_background_opacity/`。

## 2. 发现页关键词搜索

- 产品行为：发现页顶部新增搜索入口；搜索页输入后 320ms 防抖请求，结果复用发现页双列卡片，支持分页加载、空结果、失败重试与清空关键词。青少年模式下发现页本身不可用，搜索入口也不展示。
- 匹配字段：角色名称、简介/宣传语（tagline）、分类；最多 50 字。官方角色目录仍按分类缓存完整集合，关键词只在内存过滤，避免搜索词污染共享 Redis 目录。
- 接口：1.3.0 客户端统一调用 `GET /chat/v1/characters/search?q=<角色名>&page=&page_size=`（注册引导原本已用该路径；服务端 `master` 已有该接口，按名称/标签匹配，`q` 必填 1–30 字，双端输入框已按 30 字截断）。本次没有新增列表 `keyword` 参数，避免与既有搜索契约重复。
- 代码位置：
  - iOS `Bubbly/Views/Discover/DiscoverSearchView.swift`、`Views/Discover/DiscoverView.swift`、`Services/CharacterService.swift`。
  - Android `ui/screens/DiscoverSearchScreen.kt`、`ui/screens/RoleListScreen.kt`、`data/network/CharacterApiService.kt`、`data/repository/CharacterRepository*.kt`、`ui/screens/DiscoverCatalog.kt`（复用 `DiscoverGridCard`）。
  - 服务端本轮不新增搜索路由：`src/modules/character/routes.ts` 的 `/search` 与匹配逻辑已在 `master`；本轮只补 `POST /characters/custom` 的 `is_public` 意愿写入。

## 4. 他的来信「曝光时写信」（`letter_lazy_v1`）

- 契约 owner：`moodly-chat-svr` 的 `docs/letters/曝光时写信_三端协议_20261111.md`（提交 `0a7592c7`）。本节只记客户端落地，不复制接口细节。
- 能力位：`x-client-capabilities` 增加 `letter_lazy_v1`（与 `letter_v1` 一起带；iOS 仍按 1.0.9 起下发整串，Android 无条件带）。
- 卡片：`extra.letter_card.content_state` 取 `writing` / `ready` / `withdrawn`，缺省与不认识的值都按 `ready`；`writing` 时标题为空、恒为未拆，按未拆信浮起并预取详情（详情里也有 `envelope`）。
- 接口：新增 `POST /chat/v1/letters/{letterId}/expose`（`client_request_id` + `source` = `float|card|list|push`，幂等）；`GET /chat/v1/letters/{id}` 在 `writing` 时返回 200 并带 `retry_after_ms`（服务端给 1500）；对 `writing` 调 `open` / `finish` 返回 409 `letter_writing`，客户端只在 `ready` 后调。
- 客户端行为：浮层、消息流卡片、列表、推送四个入口首次真正露在屏幕上时各调一次 expose（每封每进程一次，失败静默重试一次）；「稍后再看」改回线上信封卡气泡落进消息流，删掉右下角小信封；开信动效约 2.0s（火漆碎裂 + 信纸抽出），`writing` 时停在蓄力并显示「他还在写…」，按 `retry_after_ms` 轮询或收到 WS `message_update` 继续，30s 超时或 `withdrawn` 则收起并轻提示「这封信没寄出来」；`withdrawn` 的卡片、浮层、阅读器等待态和本地缓存消息一并移除。
- 代码位置：
  - iOS `Models/LetterModels.swift`、`Models/LetterFloatPolicy.swift`、`Services/LetterService.swift`、`ViewModels/LetterReaderViewModel.swift`、`ViewModels/LetterFloatController.swift`、`Views/Chat/Letter/LetterOpenCeremonyView.swift`、`Views/Chat/ChatDetailView.swift`。
  - Android `data/model/LetterModels.kt`、`data/network/LetterApiService.kt`、`data/network/LetterJson.kt`、`data/network/ClientCapabilities.kt`、`data/repository/LetterRepository.kt`、`ui/letter/LetterFloatLayer.kt`、`ui/letter/LetterFloatPolicy.kt`、`ui/letter/LetterOpenRitual.kt`、`ui/letter/LetterViewModel.kt`。

## 5. 注册引导 1.3.0 改版（`onboarding_3arm_new_users_20261110`）

- 方案 A（choice）：「你想遇见谁？」改成一大两小拼图——「在商店挑选角色」为暖色渐变主推大卡（200 高、圆角 28、抽象剪影 + 星光、「新人推荐」胶囊），「搜索角色」「创建角色」并排两张小卡（156 高、圆角 24、右下放大水印）；标题 34，去掉副标题与底部「拿不准？」提示。两端尺寸与文案逐项一致。
- 方案 B（cards）：官方角色改成交友式划卡（一次一张大图卡，左滑 / ✕ 跳过，右滑 / ♥ 选中）；点 ♥ 先进角色详情，详情底部按钮在引导里叫「下一步」，再回到「你叫什么名字」。
- 流程：只剩「你叫什么名字」一步，名字直接存成昵称并开聊（不再有「他该怎么叫你」），单步不显示进度条；长度上限 12 → 15 字（iOS `OnboardingText.maxLength`、Android `MAX_NAME_LENGTH`）。

- 外观默认：没选过外观的用户从「跟随系统」改为浅色（iOS `AppAppearance.defaultValue`、Android `AppearanceMode.Default`），选过的照旧。**这会让从未打开过深色模式设置的老用户升级后变浅色**，属产品决策，验收时按此口径核对。
- 判定与埋点：登录后并行拉资料与启动配置、最多等 6s（Android，原串行 2s），并记 `onboarding_gate_decision`（`entry` / `server_variant` / `server_resolved` / `strategy_ok` / `profile_ok` / `timed_out` / `elapsed_ms` / `result`；iOS 无同名事件）。
- 调试：Android 用 `-PTEST_ONBOARDING_VARIANT=choice|cards` 打的测试包，登录后固定进对应组（正式包为空、不生效）。

## 发布顺序与兼容

1. 先执行服务端迁移 `20261112_chat_background_opacity`（新增列，默认 1，不影响旧数据）。
2. 发布聊天服务。未升级客户端不传新字段，读取旧会话按 1 显示；创建不传 `is_public` 仍私有。
3. 再发布 iOS / Android 1.3.0。审核后台和公开列表门禁无需改动；审核通过仍以 `is_public=true AND public_reviewed_at IS NOT NULL` 为准。
4. 版本号：Android `versionCode 34` / `versionName 1.3.0`（1.2.9 发布线按抖音渠道记录占用 33，1.3.0 顺延 34），iOS `1.3.0 (41)`（主 App 与通知扩展）。聊天服务的 `LETTER_LAZY_MIN_APP_VERSION = 1.3.0` 与 `android_feature_flags_by_version["1.3.0"]` 都依赖这个版本号；不升版本会变成「进聊天页走占位、22 点推信仍预写」的混合行为。
5. 曝光时写信的服务端热配置 `lazy_enabled` 默认关：先发客户端、确认 1.3.0 覆盖率后再开。开关未开时客户端行为与 1.2.9 一致，只是多带一个能力位。
6. Android 发版顺序注意：1.2.9 分支 `versionCode 32`，1.3.0 是 33；若 1.2.9 晚于 1.3.0 发商店，Play 会按版本号降级拒绝。
