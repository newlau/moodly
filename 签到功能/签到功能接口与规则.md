# 签到功能接口与规则

Status: current

## 签到规则定义

### 7天签到周期

| 天数 | 普通奖励 | VIP 奖励（×1.2） |
|------|----------|-------------------|
| 第1天 | 40 | 48 |
| 第2天 | 50 | 60 |
| 第3天 | 40 | 48 |
| 第4天 | 40 | 48 |
| 第5天 | 50 | 60 |
| 第6天 | 40 | 48 |
| 第7天 | 70 | 84 |

### 中断重置规则

- 连续签到中断后，次日从第1天重新计算
- 同一天重复点击签到，不重复发奖（幂等）
- 第7天完成后，下一次签到重新从第1天开始新周期

### VIP 加成规则

- 仅有单一 VIP 等级（无 SVIP）
- VIP 用户 = 普通奖励 × 1.2，向下取整
- VIP 判断依据：`user.isVip === true`

### 邀请码入口说明

- 签到页底部展示邀请码入口
- 文案：`新用户填写后自动得 100 糖果`
- 邀请码兑换走 `/v1/invite-code/redeem`
- 新用户填写邀请码后，填写人和邀请人各得 100 糖果
- 服务端 `share_entry.reward_amount` 返回 `100`，客户端仅用于展示

## 幂等与事务说明

### 幂等性

- 同一用户同一天（Asia/Shanghai 时区）只能签到一次
- 重复请求返回 `ALREADY_CHECKED_IN` 错误
- 判断依据：`check_in_records` 表中是否存在当天记录

### 事务一致性

签到成功时，以下操作在同一数据库事务中完成：
1. 写入签到记录（check_in_records）
2. 更新用户糖果余额（users.candy_balance）
3. 写入糖果流水（transactions，type='checkin'）

### 连续签到判定逻辑

1. 查询用户最近一条签到记录
2. 如果最近签到日期 = 昨天 → 连续天数 +1
3. 如果最近签到日期 = 今天 → 已签到，拒绝
4. 其他情况 → 连续天数重置为 1

### 7天周期推进

- `current_cycle_day = ((streak_days - 1) % 7) + 1`
- 第7天完成后，下次签到 streak_days 继续累加，但 cycle_day 回到 1

## 奖励计算示例

### 示例1：普通用户第4天签到
- base_reward = 40（第4天奖励）
- vip_bonus = 0
- reward_candy = 40

### 示例2：VIP 用户第7天签到
- base_reward = 70（第7天奖励）
- vip_bonus = Math.floor(70 × 0.2) = 14
- reward_candy = 84

### 示例3：连续签到8天（进入第二轮）
- streak_days = 8
- current_cycle_day = ((8-1) % 7) + 1 = 1（新周期第1天）
- base_reward = 40

## 数据表设计

### check_in_records（新增）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | VARCHAR | 用户 ID |
| check_in_date | DATE | 签到日期（Asia/Shanghai） |
| cycle_day | INT | 本轮第几天（1~7） |
| base_reward | INT | 基础奖励 |
| vip_bonus | INT | VIP 加成 |
| total_reward | INT | 实际发放 |
| is_vip | BOOLEAN | 签到时是否 VIP |
| created_at | DATETIME | 创建时间 |

唯一约束：`(user_id, check_in_date)` — 保证同一天不重复

### transactions 表（复用，新增 type='checkin'）

签到流水 label 统一为 `每日签到奖励`
