# 签到功能开发记录

状态：implementation record（2026-06-05 已同步糖果充值会员额外 20% 加赠移除口径；签到 VIP 加成属于独立规则）

## 背景与目标

在现有糖果购买体系基础上，补齐"签到赠送糖果"逻辑，恢复 Android / iOS 之前被关闭的签到入口，形成完整的签到系统。

## 调研结论（2026-04-15）

### 1. 现有糖果系统

- **余额字段**：`users.candy_balance`（整数）
- **流水表**：`transactions` 表，字段包括 type/amount/balance_after/ref_id/label
- **充值逻辑**：`CandyService.fulfillCandyOrder()` 在事务中完成：更新余额 → 写流水
- **流水类型**：目前仅有 `topup`（充值）
- **充值会员加赠**：糖果充值会员额外 20% 加赠已移除；签到 VIP 加成属于独立规则

### 2. 签到现状

- **服务端**：完全不存在。无签到表、无签到接口、无签到路由
- **iOS**：四层代码完整（Model/Service/ViewModel/View），调用 `/check-in/info` 和 `/check-in/do`，但服务端无对应接口。入口被 `isUnfinishedProfileEntryEnabled`（release=false）隐藏
- **Android**：入口在 ProfileScreens.kt 被 `unfinishedProfileEntriesEnabled` 隐藏，点击弹 Toast "暂未开放"。backup 目录有简易 `AlignedCheckInScreen.kt` 原型但未接入。无 API/ViewModel/Repository

### 3. VIP / SVIP 体系

- **仅有单一 VIP 等级**，无 SVIP
- VIP 判断：`user.isVip` 布尔字段
- VIP 到期：`user.vipExpireAt`
- VIP 状态表：`vip_status`（isActive/expireDate）
- **结论：只实现 VIP +20%，不扩展 SVIP**

### 4. 入口关闭点

- **Android**：`AppFeatureFlags.unfinishedProfileEntriesEnabled` → release 包 `HIDE_RESTRICTED_FEATURES=true` → 签到入口隐藏
  - 位置：`ProfileScreens.kt:631`
- **iOS**：`AppConfig.isCheckInEntryEnabled` → `isUnfinishedProfileEntryEnabled`（`#if DEBUG true #else false`）
  - 位置：`ProfileView.swift:231`

### 5. 最小改动方案

#### 服务端
- 新增 `check_in_records` 表（签到记录）
- 新增 `checkin` 模块（service + routes + schema）
- 复用现有 `transactions` 表写签到流水（type='checkin'）
- 复用现有 `user.candyBalance` 余额更新
- 注册路由到 app.ts

#### Android
- 新增 `CheckInApiService`（Retrofit 接口）
- 新增 `CheckInModels`（数据模型）
- 新增 `CheckInRepository`
- 新增 `CheckInViewModel`
- 新建 `CheckInScreen`（基于 backup 原型重写，对齐 iOS 风格）
- 修改 `ProfileScreens.kt` 签到入口 → 导航到签到页
- 修改 `MoodlyNavHost.kt` 注册签到路由
- 修改 `NetworkModule.kt` / `RepositoryModule.kt` 注册 DI
- 修改 `AppFeatureFlags.kt` 新增签到独立开关

#### iOS
- 适配服务端新接口字段（iOS 已有完整代码，需对齐字段）
- 修改 `AppConfig.swift` 签到入口开关 → release 包可见
- 补充分享入口占位 UI
